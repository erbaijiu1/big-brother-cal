# 产品分类自动补全同步方案

## 1. Requirements Clarification

- 同步入口确认：`tool/get_all_trade_info.py` 负责从旧系统拉取托运排单和绩效数据。
- 目标：以后只运行一次完整同步命令，即可先更新原始数据，再补全缺失的一级产品分类。
- 已有非空一级分类不得被新一轮同步中的空值或原始描述覆盖。
- V1 一级分类固定为：冻品、熟食、水果、酒类、食品、生鲜肉类、水产海鲜、普货。
- 只自动采用高置信历史映射；UNKNOWN 和低置信结果继续留待人工复核。
- 本方案不新增数据库字段或表；原始源字段继续保存在 `row_text_json` / `raw_row_json`。

## 2. Requirements Analysis

### 功能拆分

1. 历史分类复用 → 版本化映射词典 → 固化已批准的高置信原始品名映射。
2. 新数据即时归一 → 共享分类模块 → 规范品类、精确映射、关键词规则依次处理。
3. 缺失分类补全 → 托运单描述关联 → 精确关联后再走共享分类和可选大模型。
4. 防止分类倒退 → 绩效表 UPSERT → 只填补空分类，永不覆盖已有非空分类。
5. 一次命令运行 → 全量同步编排 → 托运单、绩效、补全按顺序执行并失败即停止。

### 使用路径

1. 操作人员提供旧系统 `PHPSESSID`。
2. 运行完整同步命令。
3. 系统先同步托运排单，再同步绩效数据。
4. 绩效源携带的原始品名先在内存中归一；能识别的直接作为一级分类入库。
5. 对仍为空的绩效记录，使用公司单号精确关联托运单描述，再进行补全。
6. 输出新增、更新、已分类、仍未知数量；人工只需处理剩余未知清单。

### 操作规格

- 已有分类 + 新源空值/原始品名 → 保留已有分类。
- 新记录 + 已知原始品名 → 写入对应一级分类。
- 新记录 + 未知描述 → `product_name` 保持空，不默认写入普货。
- 模型不可用 → 完成映射和规则分类，未知保留；同步不能伪装成全部成功分类。
- 任一数据集抓取失败 → 完整同步返回失败，不继续宣称整链路成功。

## 3. Technical Specification Design

```text
旧系统
  ├─ 托运排单 ──> t_consignment_trade
  └─ 绩效记录 ──> 原始品名
                     ↓
        规范品类 → 高置信映射词典 → 关键词规则
                     ↓
        只补空值 UPSERT → t_performance_statement
                     ↓
        空分类 + 精确订单关联 → 同一分类器 → 可选非思考模型
```

分类伪代码：

```text
规范化输入文本

若文本已经是八个一级分类：返回该分类
若精确命中版本化映射：返回映射分类
若命中高确定性关键词：返回规则分类
否则返回 UNKNOWN

只有补空流程且配置了模型时：
    将 UNKNOWN 描述批量交给非思考模型
    仅接受允许分类且置信度达到阈值的结果
```

写入伪代码：

```text
插入新记录时写入当前可识别分类

记录已存在时：
    若数据库分类非空：保留数据库值
    若数据库分类为空且新分类非空：补入新分类
    否则保持为空
```

## 4. Component / Module Design

- `product_category_normalizer.py`：唯一分类定义、映射加载、规则分类、输入归一。
- `product_category_mapping_v1.csv`：本次已批准的高置信历史映射，只读版本化资产。
- `get_all_trade_info.py`：抓取、解析、只补空 UPSERT、全量同步编排。
- `product_name_enrichment.py`：精确关联托运单，对剩余空分类做补全；复用共享分类器。
- `tool/README.md`：一键同步、dry-run、模型开关、结果核对说明。

## 5. Technology Selection Comparison

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 使用迁移备份表作为在线词典 | 无需新增文件 | 运行时依赖一次性迁移表，后续清理会失效 | 不采用 |
| 新增数据库映射表 | 可后台维护 | 需要 DDL 和新的管理流程 | V2 可选 |
| 版本化 CSV + 共享模块 | 可审计、可测试、部署简单、无需数据库变更 | 修改映射需发布代码 | V1 采用 |

## 6. Risk and Boundary Analysis

- 旧系统源字段改变名称时，解析层会得到空分类并告警，不得猜测字段。
- 同一描述可能业务含义变化；已有非空分类优先，自动同步不覆盖人工结果。
- 映射文件损坏或出现冲突时，同步启动即失败，避免部分错误分类。
- 模型只处理映射和规则无法识别的描述；未达到阈值的结果不写数据库。
- 完整同步属于写操作，默认仍保持 dry-run；只有显式 `DRY_RUN=0` 才写库。
- `company_tracking_no ↔ order_no` 是唯一允许的补全关联，不使用托运编码回退。
